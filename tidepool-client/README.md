# Tidepool client

The reference human client for Tidepool: a GPUI application that lives in the
macOS menu bar or the Windows notification area, opens a popover when its icon
is clicked, and shows its main window when asked. It starts icon-only — there is
no Dock or taskbar entry at launch — and it is the worked example for Zoid's
`tray` template.

## Generated from Zoid

| | |
|---|---|
| Generator | Zoid **9.0.0** |
| Template | **`tray`** (`templates/tray` in the Zoid repository) |
| Surfaces | **menu + popover + window** (`app_shape = menu,popup,window`) |
| Launch | **icon-only** (`open_on_launch = false`) |
| Project record | [`zoid-project.json`](zoid-project.json) records the generator version and codegen paths |

To reproduce it, run Zoid's create flow and pick those surfaces:

```sh
zoid create tidepool-client --template tray
```

Zoid 9.0.0's CLI does not expose the app-shape flags: the surface checkboxes are
part of the editor's Template Pick step, and the wizard passes `app_shape`,
`has_menu`, `has_popup`, `has_window` and `open_on_launch` to the same template
renderer. This project was rendered with that exact request (see
`zoid-project.json` for the template and version), so a wizard run with **Menu**,
**Popover** and **Window** ticked and **Open on launch** unticked produces the
same sources. The name in `Cargo.toml` is `tidepool-client`; the project name
rendered into the UI is `Tidepool`.

`zoid create` also copies `zoid-gpui` and `zoid-core` into `vendor/`. Those
copies are part of the generated project: the client builds against them without
depending on the Zoid workspace.

## Building and testing

The client is its own Cargo workspace. It is intentionally **not** a member of
the pool's workspace at the repository root, so the server's `cargo test` gate
does not build a GPUI application.

```sh
cd tidepool-client
cargo run
cargo test
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
```

The tests are headless:

- `tests/tray.rs` mounts the template's modules and exercises the tray icon,
  the popover view and the main window, and decodes the shipped icon assets.
- The unit tests in `src/main.rs` pin the generated app shape: the app starts
  with no window (`OPEN_ON_LAUNCH == false`), the menu is installed, a click
  resolves to the popover, and the menu's **Open App** item resolves to the main
  window.
- The icon tests prove the menu-bar asset is the clawffice-design cell sprite at
  the 16pt size the tray code pins, with crisp (non-antialiased) pixels and all
  four sprite colours, and that the Retina asset is the same artwork at exactly
  2x. The Windows icon is checked for the sizes a tray icon needs.

## `ui/app.json` is the editable UI source

`ui/app.json` is the only file to edit when changing the popover's content,
size or kind. `src/ui/zml_layout.rs` and `src/ui/window_options.rs` are
**generated by Zoid** from it and are **not hand-edited**: each carries Zoid's
generated-file banner, and a test asserts the banner and the source title stay
in step. Regenerate them with:

```sh
zoid export --project .
cargo fmt
```

`zoid export` is deterministic: running it twice on the same `ui/app.json`
produces byte-identical modules. Its output is not rustfmt-formatted, so run
`cargo fmt` afterwards — that is the only hand step, and it is formatting only.
A diff after editing `ui/app.json` and running both is exactly the UI change you
asked for.

## Behaviour

- **Icon-only start** — `OPEN_ON_LAUNCH` is `false`, so the process creates its
  tray icon and no window. On macOS the activation policy is `Accessory`; for an
  app bundle, add `LSUIElement = true` to `Info.plist`.
- **Menu** — the native context menu has **Open App**, **Settings…** and
  **Quit**. It is installed whenever the menu surface is present.
- **Popover** — a left-click on the icon toggles the popover, anchored to the
  icon. Duplicate clicks within 300ms are coalesced (Windows delivers two events
  for one physical click).
- **Main window** — **Open App** opens the main window; with no window surface
  it would open the popover instead. The app never quits when the last window
  closes; quitting is explicit.
- **Single instance** — a lock file in the app data directory enforces one
  instance. A stale lock is reclaimed; a second launch signals the first to show
  its surface.

## Tray icon

The icon is the suite's design, not a placeholder:

| Platform | Asset | Source |
|---|---|---|
| macOS menu bar | `assets/tray-icon.png` (16x16) and `assets/tray-icon@2x.png` (32x32), marked as a template image | the clawffice-design 12x12 `pool` cell sprite, rasterised one pixel per cell with no antialiasing |
| Windows tray | `assets/tray-icon.ico` (16–256px) | clawffice-design `logos/tidepool/tidepool-icon.ico` |

`assets/cells.json` is the pinned `tokens/cells.json` from clawffice-design at
commit `995b41606e65`; `assets/SOURCE.json` records that commit and the hashes
of the copied files. The sprite uses the Biolume palette's roles: `#` is the
`tide` product hue (`#4A9FE0`), `o` the `claw` accent (`#F26B21`), `w` `mist-50`
and `k` `ink-950`. Regenerate the PNGs with:

```sh
python3 assets/render_tray_icons.py
```

The script uses only the Python standard library. macOS tints the menu-bar
image for light and dark menubars; the artwork is a solid creature rather than
full-colour detail for that reason.

## Structure

| Path | Purpose |
|---|---|
| `src/main.rs` | Entry point, app shape, tray manager, menu dispatch, poll loop |
| `src/tray_icon.rs` | Platform abstraction: `NSStatusBar` on macOS, `Shell_NotifyIconW` on Windows, no-op fallback on Linux |
| `src/popover_view.rs` | The click-anchored popover |
| `src/main_window.rs` | The main window opened by **Open App** |
| `src/settings_window.rs` | Settings window |
| `src/lifecycle.rs` | Single-instance guard |
| `src/icon_assets.rs` | `include_bytes!` seam for the tray icon |
| `src/ui/` | **Generated** from `ui/app.json`; do not hand-edit |
| `ui/app.json` | The editable popover structure |
| `assets/` | Tray icons and their provenance |
| `vendor/` | Zoid's `zoid-gpui` and `zoid-core` crates, copied at generation time |
| `tests/tray.rs` | Headless tray, view and icon tests |

## What a person still has to look at

Two properties are about the running app and cannot be asserted headlessly:

1. Launch the app and confirm that no window and no Dock/taskbar entry appear,
   that clicking the icon opens the popover, and that **Open App** opens the main
   window.
2. Confirm the menu-bar icon is legible at menu-bar size on both a light and a
   dark menubar.

Everything behind those behaviours (which surface opens at launch, which surface
a click and the menu item resolve to, and the icon's size, crispness, colours
and scales) is covered by tests.
